Project document store

Firebase Storage holds the files and Firestore holds the metadata and the review comments. Until the Firebase project is configured, the same interface runs against browser storage so nothing blocks the engineering work — but that fallback is per-browser and not a shared record.

Firebase is not configured
Create a Firebase project, enable Firestore and Storage, then paste the web app config into the environment as NEXT_PUBLIC_FIREBASE_API_KEY, NEXT_PUBLIC_FIREBASE_PROJECT_ID, NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET and the remaining config values listed in .env.example. Deploy the rules in firestore.rules and storage.rules before going live. The web config is public by design — the rules are what protect the data, so do not rely on obscurity.
